## Public boundary and validation

- Proposed bridge: `window.gabPrd.prds`, alongside the unchanged `bootstrap` bridge; globals/preload wiring is future builder work.
- Product version/channels are independent of bootstrap: `gabprd.product.v1.request`, `.event`, `.detach`; version 1 exactly.
- Preload binds each named method separately; it never exposes generic invoke, raw IPC, filesystem/SQL/executable/configuration access.
- Runtime input is `unknown`. Future parsers must accept exact own enumerable data properties on plain records, inspect descriptors without invoking getters, reject symbols/prototypes/extras, and validate every nested union and bound. Types are not runtime validation.
- Main checks the live owned WebContents, current main-frame identity, exact `gabprd://app/main_window/index.html`, current frame/window URL and non-destroyed ownership on every request/detach/subscription. No substring or origin-only trust.
- Preload validates replies/events too. Failures use only the literal code/message pair in `PRD_ERROR_MESSAGES` plus an app-issued correlation ID; invalid request IDs are not echoed. Result requestId/command may be null only on rejection before valid correlation.
- Renderer chooses opaque IDs/tokens issued or accepted by main, never authoritative paths. Repository display path is verified selected-checkout information; document/convention paths are contained relative display information, not file-open authority.
- App IDs/request/subscription/operation/generation/question/option/candidate/convention IDs are canonical lowercase UUIDs. Session IDs are the actual validated SDK UUIDs, treated as opaque publicly; message/history IDs are stable opaque SDK-identity mappings capped at 128 bytes, not filename inference. Exact SDK identities stay recorded privately. Revision/version tokens are app-issued UUIDs; cursor maximum is 256 UTF-8 bytes and bound to owner, query, snapshot and ordering.
- Event sequence is a nonnegative safe integer; overflow ends the subscription with resync, never wraps. All strings reject NUL; file/name validation also rejects forbidden Windows names/characters. UTF-8 byte limits apply before allocation/work; no coercion or JSON stringification of unknown values.
- Fixed errors never include raw causes, stacks, provider payloads, stderr, remote credential URLs, settings/auth paths or tool arguments. Drain utility output without forwarding. Conversation/document/UI text is untrusted writer-visible content, not an error tunnel; never project raw tool results, thinking blocks or credentials as ordinary status/history.

## Command/reply semantics

All requests include exact `contractVersion`, `requestId`, `command` and the command-specific body. Success returns the matching typed reply; rejection returns a fixed safe error. Admission of a long operation is not its completion.

| Command | Required semantics / success reply |
|---|---|
| NativePickRepository | Main-owned native folder dialog; cancellation is `{outcome:'cancelled'}`, not an error. Validate/register the chosen clone before returning RepositoryView; invalid selection does not register or change defaults. |
| SetDefaultRepository | Validate repository or explicit null; compare settings expectedVersion. Return new DefaultRepositoryView. Existing PRD associations never change. |
| ListPrds | Stable bounded page plus remembered default and store health. No session startup or workspace mutation. |
| CreatePrd | Accept registered repository + initial idea only, with no writer-title field. Derive the bounded app listing/file label from the actual idea; the verified generated heading can later supply the listing label. Validate repository/idea/store before recording intent; reserve identities, fetch fresh origin/main and provision. Return durable snapshot/operation; creation can still be running. No prompt before required skill/configuration/link validation. |
| OpenPrd | Validate chain and exact session before opening; attach caller-owned subscription before capturing snapshot sequence. Restore actual context, never replay an interrupted turn. Return subscription/snapshot; bad links do not reset anything. |
| ReadHistory | Validate PRD/session association; active-branch persisted projection, including completed pre-compaction turns, with opaque cursor. An allocated session can return an empty page; missing/corrupt materialized sessions fail. |
| ReadDocument | Resolve registered document from IDs; validate/read actual file; return whole bounded UTF-8 body/revision, not a renderer path. Missing expected file fails, not an empty document. |
| SaveDocument | Check record version, document association and disk revision under app admission serialization. Return reread body/snapshot only after verifying the observed save and recording metadata. Never implicitly save a different buffer. |
| ListDraftCandidates | Bounded verified real-file metadata/previews and convention choices, not chat-generated paths. Return record version and explicit coverage. |
| SelectDraft | `selection:'convention'` selects a listed folder with null document expectation before registration; can continue pending initial brainstorm. `selection:'candidate'` validates listed candidate and exact disk revision; registers/readbacks that file. Return snapshot, nullable body and nullable newly admitted operation. |
| SendTurn | Verify session, recordVersion and expectedDocumentRevision (null only when no document registered). Reject busy/stale/conflicting app state before prompt. Literal writer text; intent distinguishes conversation/revision, not different write permissions. Return admitted operation/snapshot. |
| AnswerUiQuestion | Verify current session/operation/generation/question, expectedVersion and exact answer kind/option. Return answered/cancelRequested; not a new chat turn, and never guessed approval. |
| CancelOperation | Validate PRD/operation ownership. Idempotent cancel request or alreadyFinished result. Stop admission; final outcome follows awaited reconciliation, not kill acceptance. |
| ReconcilePrd | ID/link-guarded reread (no stale version prerequisite) of workspace/document/session/operation state; return authoritative snapshot. Does not overwrite dirty renderer text, restart prompts or repair corrupt files. |
| RetryWorkspaceSetup | Match recorded setupOperationId/version; inspect partial effects before admitting explicit continuation. Reuse only verified owned branch/worktree/base. Never retry a turn automatically. |

Request IDs identify attempts, not authorization. Same caller/request/exact body returns the same admission/result while retained; changed body is INVALID_REQUEST. Keep at most 256 replies per caller; never log bodies. Long mutating admissions retain originating requestId in SQLite and reject ambiguous replay after restart/eviction with STALE_VERSION until refresh/reconciliation. Saves record completed admission in operations; default changes atomically record settings version/last_request_id; old expected versions reject retry rather than apply twice. Reads can be repeated. Never infer exactly-once external effects from deduplication.

## Domain, versions and foreground editing

- Repository identity is the selected checkout plus canonical common Git directory/origin fingerprint; two checkout registrations may share a common directory without being interchangeable.
- PRD lifecycle: createPending → brainstormActive → draftAvailable, with failed/interrupted retaining all existing links. Recovery returns to the state appropriate to registered document presence. DraftAvailable is not brainstorm completion, writer approval or publication; publication is always unavailable.
- Workspace steps: planned → baseFetched → branchCreated → worktreeCreated → ready; uncertain/invalid effects become recoveryRequired.
- Session notAllocated means there is no recorded allocation. Allocated has a real SDK identity/planned path but legitimately no JSONL. Materialized requires validated persisted data; missing/corrupt/linkageMismatch after expected persistence are not nullable new-session states.
- Document notRegistered means no authoritative draft has been selected. Missing/invalid retains expected ID/path and blocks saves/sends; never coerce it to notRegistered.
- Operation phases: starting/running/awaitingUiResponse/cancelling/reconciling/finished. Only finished has non-null outcome; failed/interrupted carry fixed errors. A pending question requires awaitingUiResponse and matching active Pi correlation. Ordinary assistant questions require a subsequent writer SendTurn, not a fabricated UiQuestion or fragile “ready” phrase.
- PrdSnapshot includes required nullable display-only `workspaceLocation: {worktreePath,branchName}` from its retained workspace record, present only at worktreeCreated/ready and null at other setup states. The exact bounded fields are parsed with workspace-state coherence; they confer no input/file/Git authority. Display the worktree folder and persisted branch visibly during folder confirmation, brainstorm, draft and reopen, not the selected source checkout as the active location. Source/default repository remains separate and unchanged for new PRDs; missing/unverified setup never falls back to a misleading source location.
- RecordVersion changes transactionally on authoritative metadata/link/revision/lifecycle/foreground admission/phase/question changes, not each text delta. Settings has its own version. Snapshots expose the newest version for follow-on app mutations.
- DocumentRevision maps to private file identity + SHA-256 + byte length + nanosecond mtime. Timestamp alone is insufficient. Re-observing the same identity/content/stat preserves the token; any changed fingerprint invalidates it. Null SendTurn expectation is invalid for missing/invalid/registered documents.
- Serialize application-controlled admission by PRD and shared repository identity, with a consistent repository-then-PRD lock order. Reject overlapping foreground admission with BUSY; no hidden queue/steering/follow-up prompts. UI answers/cancel/reconciliation join the existing operation deliberately.
- Save-before-send UX: renderer explicitly saves its dirty buffer, consumes the returned version/revision, then sends. If save fails/conflicts, no prompt follows. Main never claims knowledge of unsent renderer edits; renderer must not send until it has saved or deliberately retained its buffer and resolved the conflict.
- Source editor remains read-only during all foreground Pi work through reconciliation, including cancelled/failed turns. Normal SDK write/edit/bash and configured resources remain unchanged; this app lock does not bind them or other processes.
- Watchers are hints. Reread on open/read/save/send/focus/foreground settlement/cancel; reconcile filesystem changes even after failed tool results. Clean editors may reload, but dirty buffers and manual undo history remain separate from incoming disk content; never silently replace or auto-merge them.
- On conflict retain local buffer/base revision and show disk body separately. Close must save, explicitly retain local recovery, or let the writer explicitly discard; no implicit discard. Editor ownership uses typed EditorRecoveryBuffer in app-origin IndexedDB `gabprd-editor-recovery-v1`, store `buffers`, key [prdId,documentId], bounded to the document limit. Keep latest retained buffer per document, outside Git; no hidden metadata string/new arbitrary file IPC. Restore only after validating recorded PRD/document IDs through OpenPrd/ReadDocument; expose retained text as a dirty buffer, never auto-save it. If retention fails, block ordinary close with a safe error and keep the live buffer; do not claim sudden termination preserves every unsent keystroke.
- App save preserves preimage/intended bytes under owned recovery, rechecks links/revision immediately before replacement, then rereads/verifies. Conflict discovered before mutation rejects without writing the target. If interference is discovered after replacement, preserve recovery and report REVISION_CONFLICT/uncertain outcome, not success or rollback.
- Final-check/replace races with normal tools/external writers remain possible. No full CAS, global quiescence, OS sandbox, automatic overwrite prevention for all actors or background-writer control is promised.

## Bounds, events and resynchronization

`PRD_LIMITS` is normative: list 50, history 100, candidate/convention 32 items; page maximum 512 KiB; documents 2 MiB; idea/turn 64 KiB; skill 256 KiB; display name 160 bytes; filename 200 bytes. Candidate scan maximum 4096 files, previews 8 KiB, UI text 16 KiB/32 options; relative paths 1024 bytes, verified display paths 4096 bytes.
History text is capped at 64 KiB/item and events at 64 KiB with 8 KiB delta chunks (encoded envelope counts). Finalized text must fit the envelope, truncating at a valid UTF-8 boundary with explicit status. Never truncate actual saved Markdown/JSONL or silently drop completed history. Oversized documents/requests reject; paged display truncation is explicit and does not change SDK model context.
Session validation is bounded at 64 MiB total/2 MiB per line; exceeding bounds is LIMIT_EXCEEDED, not corruption/reset. Streaming parsers and SQLite queries remain bounded; scanning overflow is scanLimit, not proof there are no other candidates. Automatic single-candidate registration requires complete scan coverage.

- Correlated `extensionUi` carries a closed presentation update (status/widget key+nullable text, working/thinking nullable text, title text, notice info/warning text), not a model message. Existing bounded UI fields and full active correlation apply. Clear removes an indicator using null; never synthesize Cleared chat. Replaceable bounded activity is outside the transcript and collapsed by default; genuine notices are labeled Extension, not Pi and not saved history. No filtering assistant text by prefix or disabling configured extensions. Startup presentation updates buffered before OpenPrd result use their own monotonic UI sequence since authoritative snapshots don't contain this transient state. Not-allocated/location-confirmation application state precedes generic Pi-working labeling.
- Correlated `writerMessage` projects actual SDK user-message start with stable history-compatible messageId, original submitted text only, bounded8KiB UTF-8 plus explicit textStatus and durability:'unconfirmed'. Initial idea and follow-ups appear as You messages before a provider response. Do not emit expanded skill/context or claim disk persistence. Larger original input is preserved unmodified; only this live view is bounded to fit worst-case JSON escaping under eventBytes. Deduplicate live/saved messages by exact messageId at history refresh and render, not body text; identical separate turns remain distinct. No session format or persistence change.
- Renderer installs `onEvent` before OpenPrd; its returned unsubscribe removes only that callback. Main owns subscriptions by live caller/PRD and captures snapshot/sequence after attachment; renderer buffers correlated events until the open result then discards sequence ≤ snapshot sequence.
- `detachSubscription` accepts only exact version/subscriptionId, checks caller ownership, is idempotent and removes main subscription. Window teardown removes all subscriptions/handlers. It is not operation cancellation. No raw event object or arbitrary channel reaches renderer.
- Public events carry PRD/subscription plus nullable request/session/operation/generation when no such actor exists; streamed messages/questions must carry all active Pi correlation. Sequence is monotonic per PRD independently of utility-local sequence/generation; main persists its high-water mark before publication and reissues it, never forwards SDK unions. Every event carries current RecordVersion; operation/question changes must also publish a snapshot so the renderer has a complete answer/send precondition.
- Discard duplicates/late events only after checking IDs/generation. A sequence gap or bounded-queue overflow requires an authoritative snapshot and history/document reread, never guessed completion. ReconcilePrd returns the same stream sequence; apply later buffered events in order.
- Queue maximum 256 events/512 KiB per subscription and utility stream. Coalesce/drop only transient deltas with explicit resyncRequired; preserve finalized/persisted state by bounded rereads rather than unbounded RAM. If terminal notifications cannot be queued, invalidate subscription and require reopen. Snapshot is authoritative, not token-stream reconstruction.
- textFinalized replaces stream text but has durability unconfirmed. historyPersisted refers only to verified appended entries. Neither message_end, agent_end, agent_settled nor prompt resolution alone proves persisted success/document creation.
- UiQuestion kinds are select/confirm/input/editor; responses are closed unions with explicit cancel. Options have opaque IDs, not labels as authority. Deadlines/signals dismiss visibly; expired/foreign responses and repeated answers under a new request ID reject without forwarding (same-request replay follows the deduplication rule). No confirmation/approval derives from actor completion or ordinary chat.
- SDK confirm returns boolean and has no cancellation value: never turn cancellation into false. Reject/cancel that dialog's operation and await abort/reconciliation. Select/input/editor cancellation may map to SDK undefined only for a real cancellation, with public dismissal. Unsupported terminal custom UI does not auto-cancel or auto-answer.

Backpressure abort/interruption is explicit, never hidden lost completion.

Forced timeout/exit records interruption/uncertain effects; do not kill unrelated PIDs or claim independently launched writers stopped.

## App-data layout and schema 1

Proposed root is normal `<Electron userData>/product-v1/`, outside selected checkouts/worktrees, not bootstrap's temporary userData override:

```text
owner.json                        # ProductOwnerMarker
metadata.sqlite3                  # application metadata only
workspaces/<workspaceUUID>/       # retained Git worktree
sessions/<prdUUID>/               # SDK's exact allocated JSONL filename
recovery/<operationUUID>/         # retained preimage/intended save bytes and typed recovery record
```

Main/persistence owner initializes; renderer/utility cannot choose roots. Exclusively reserve an empty owned root/marker, write initialization intent/databaseExpected before exclusive database creation, initialize schema and matching store_identity transactionally, then verify before marking ready. Marker/DB disagreeing after crash is incompleteInitialization, not a new store. Validate canonical root, marker/file identity, containment, no junction/symlink escape, schema/integrity and ownership before writable opening. Expected missing/corrupt/foreign/unsupported DB enters readOnlyRecovery; do not reseed, migrate, repair or delete implicitly. First milestone performs no migration from external Pi/user data.

Concrete schema description below is not executable DDL. UUID/text token columns are TEXT; counts/booleans/header versions are checked INTEGER; text payloads have explicit byte caps. ## Git, document discovery and exact session recovery

- Persist local creation date once as real `yyyy-mm-dd`; new branches `prd/<idea-slug>-<first8-of-prdUUID>`, worktree `workspaces/<workspaceUUID>`. Derive the branch once from the initial idea, not its generated title: NFKD-normalize, remove combining marks, lowercase ASCII letters/digits, replace other runs with hyphens, trim edge hyphens, take at most 48 characters and trim trailing hyphens; use `idea` when empty. Persist the exact branchRef; retries, reopen and title changes retain it. Existing UUID-only branches remain unchanged with no migration or rename. Store graph validation accepts only the exact legacy name or exact idea-derived name for its linked immutable initialIdea/PRD ID, sharing the pure derivation helper with workspace planning. Reserve paths/branches with collision rejection (including a colliding short ID); fetch origin/main afresh and record exact resulting SHA before branch creation. Failure/absence never falls back to stale/local/master base.
- Verify selected checkout/commonGitDir/origin and Git worktree registry, linked gitDir/worktree identities/current branch/recorded base association before app open/save/send/retry. Original-checkout snapshots are per-action preservation evidence, not an authority to reset later human changes. Git fetch/worktree registration necessarily updates shared Git metadata; original branch/index/drafts/unrelated bytes must stay unchanged by app actions.
- File validation is component/canonical filesystem-based, not string-prefix matching. Reject drive/UNC/absolute/traversal/ADS, junction/symlink/reparse escape, aliasing and changed identity; recheck at use. Never conceal mismatch with cwdOverride or branch reset.
- Resolve convention from instructions/existing design locations; fallback docs/design only when none. Ambiguous choices appear in snapshot/ListDraftCandidates and require SelectDraft convention before initial generation; initial idea remains durable. No arbitrary silent folder choice.
- New file `yyyy-mm-dd-<safe-name>.md`: proposed slug is NFC-normalized/trimmed/lowercased display name, with runs outside Unicode letters/numbers/underscore/hyphen replaced by a hyphen and edge hyphens removed. Reject empty/reserved Windows basename/trailing dot-space/over-limit results, never silently truncate. Final filename ≤200 UTF-8 bytes and 255 UTF-16 units; whole contained relative path ≤1024 bytes. Persist/disclose resolved draftLocation.relativePath before prompt (or in SelectDraft convention result); private Pi brainstorm input carries that exact path/date rather than guessing from idea text. Existing revisions retain path/date. Candidate inventory before generation rejects preexisting collisions, verifies UTF-8 bounded real Markdown and naming/folder rules after changes. Hints from tools/watchers are not authority; multiple candidates require writer selection, never chat prose.
- Use `SessionManager.create(worktreeCwd, appSessionDir)` / `open(exactPath, appSessionDir)` only. Validate existence/nonempty header ID/version=3/cwd, bounded JSONL entry structure and parent/branch continuity, ownership/containment and stored linkage before SDK open. SDK open can skip/repair/migrate; validation must precede it. No continueRecent, empty reset or guessed filename.
- OpenPrd on allocated/no-file returns the retained snapshot without prompting or pretending a persisted conversation exists. Explicit RetryWorkspaceSetup may resume an allocation only when durable allocateSession effectVerified exists and no prompt intent/admission was ever recorded, using `SessionManager.create(cwd, appSessionDir, {id: recordedSessionId})` (`pi.start` mode resumeAllocated). Missing bytes alone cannot prove no conversation was written: any uncertain/sent prompt forbids this route. Verify no old expected file exists and no materialization was ever recorded; validate the manager's same ID/cwd/new planned path and transactionally update that unmaterialized path before authorizing the first brainstorm prompt. SDK timestamps can change the planned filename; no existing file is opened/reset/replaced. Any materialized/missing/corrupt state forbids this route. Completed turns require observed persisted entries; compaction/model fallback/extension-handled input is not success by default. Unsupported restoration/model fallback is CONFIG_INCOMPATIBLE until explicitly reconciled, never silently different context.

## P01 private ports and lifecycle handoffs

`src/main/prd-ports.ts` defines explicit store transaction, path identity, workspace/location, document/save/recovery, utility transport/history and application service seams. No runtime implementation is supplied by an interface. Store callbacks are synchronous: no external Git/provider/file effects inside transactions. Composition uses private `Workspace.plan` to read the original checkout snapshot before admission, `operationByRequest` for durable replay rejection, and `latestOperation` for the PRD's most recently admitted operation after restart (owned SQLite insertion order; operations are never deleted). Strictly monotonic event-sequence-only updates may retain RecordVersion when every semantic PRD field is unchanged; utility high-water bookkeeping likewise does not rotate the writer's version for each token. Implementations validate both-direction associations and versions before commit; filesystem and process checks remain real adapter tests, not parser claims.

`ProductLaunch` is main-only: ordinary `product` or explicit `bootstrapFixture` with owned fixture root. Neither is a renderer request. Startup composition owns this discrimination; bootstrap contracts/preload remain unchanged until P07.

Close channels are separate from ordinary commands. Main sends an exact versioned `CloseRequest` with freshly issued `closeId`. The initiating live frame acknowledges that same ID with `decision: ready | blocked`; a stale/foreign close ID is rejected. Save uses SaveDocument; discard/retention are renderer buffer actions. An acknowledgement cannot carry paths, bodies, SQL or privileged operations. `ready` only permits the already-initiated close after main stops admission, reconciles foreground work and confirms owned shutdown. It is not proof of successful save or global writer exit. Timeout/failed retention blocks ordinary close. P07 owns stateful caller/nonce/lifecycle checks, P10 owns dirty-buffer handling.

Parser bindings: `parsePrdRequest`, `parsePrdResult(value, expectedRequest?)`, `parsePrdEvent`, `parsePiCommand/Event(value, expectedCorrelation)`, `parseDetach`, `parseCloseRequest/Response`, `parseProductLaunch`, `parseEditorRecovery`. Parsing returns a copied, deeply frozen typed value or undefined; it never stringifies unknown values or echoes exception details. Structural correlation checks do not replace current-frame authority, database association, filesystem identity, deduplication or sequence-state checks. Those belong to the named downstream service/adapters and their automated boundary suites. With no expected request, result parsing accepts only an exact fixed-error rejection with command/requestId both null; it cannot accept success or half-correlations. Supplying an expected request enables strict command/request/target/admission correlation and rejects uncorrelated replies. An invalid supplied request is rejected, never treated as the uncorrelated mode.
